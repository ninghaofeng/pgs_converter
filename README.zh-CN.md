# pgs-converter

[English](./README.md) | 简体中文

将 SRT、ASS 和 SSA 文本字幕转换为 PGS（`.sup`）位图字幕。
命令行工具和 PGS 编码器使用 Go 编写，通过 libass 渲染字体、定位、图层、
矢量绘图、淡入淡出、移动、变换及卡拉 OK 效果。

当前为初版实现，**不是蓝光制盘或蓝光合规认证工具**。
本工具不编码视频、不进行 OCR，也不直接封装 MKV。

## 桌面 UI（初版）

可选的 Fyne 2.8 桌面应用复用 CLI 转换引擎和批处理调度器，
使用 Go 界面组件，不使用 WebView，不需要 Node.js、浏览器或 WebView2。
已有 CLI 命令及默认仅打包 CLI 的行为不变。

```sh
# macOS：同时打包 CLI 和桌面应用
bash scripts/build-macos.sh --gui
```

```powershell
# Windows：同时打包 CLI 和桌面应用
.\scripts\build-windows.cmd -Gui
```

缺少依赖时可叠加原有的显式安装选项。
macOS 打开生成包中的 `PGS-Converter.app`；
Windows 打开 `pgs-converter-gui.exe`。
macOS 目前仅使用开发用临时签名，不是 Developer ID 签名或公证，
公开分发前仍需完成平台签名和发布检查。

界面支持 **简体中文和 English**。首次启动时，中文系统默认使用简体中文，
其他系统默认使用英文。在右侧设置面板顶部的 **界面语言 / Language**
中可即时切换，无需重启，不会清空队列、中断转换或重置预览。
语言选择会立即保存，不依赖是否开始转换。
也可使用 `-language zh-CN` 或 `-language en` 参数启动 GUI。
应用控件、任务状态、预览说明、输入校验和应用弹窗随所选语言切换。
转换引擎／libass 原始诊断以及已有日志保持原样，
系统原生文件选择面板的控件语言和外观跟随操作系统。

语言选项下方的 **界面缩放** 可即时调整界面文字、图标和控件间距，
支持 75%、80%、90%、100%、110%、125% 和 150%。
默认 100%，保持原有外观；如果觉得界面偏大，建议尝试 80% 或 90%。
选择会立即保存，下次启动自动恢复，不依赖是否开始转换，
并与系统显示缩放叠加。它不改变字幕字号、字幕预览渲染或 SUP 输出，
转换过程中也可以调整。

界面支持拖放文件／文件夹、递归发现、移除队列文件、
分辨率、精确分数帧率、SDR／实验性 HDR10 和参考白亮度、
输入编码、额外字体目录、SRT 字体／字号／边距、
输出目录、覆盖保护、并发、单文件进度、取消及可复制的诊断日志。
通过验证的设置会保存到下次运行。
GUI 输出平铺到指定目录，同名输出在开始前阻止转换；
CLI 的文件夹批处理仍保留相对目录结构。
macOS 和 Windows 的文件／目录选择均使用 **系统原生面板**，
覆盖字幕文件（支持多选）、输入文件夹、输出目录和字体目录。
macOS 直接使用附着于应用窗口的 AppKit `NSOpenPanel`，
不运行 AppleScript，不需要“自动化”或“辅助功能”权限；
Windows 使用附着于应用窗口的系统文件选择对话框。
取消选择不会修改队列或设置，调用失败会明确提示。
原生面板跟随系统显示缩放，不受应用内界面缩放控制。
只依赖系统框架／DLL，不需要额外的第三方动态库或外部文件选择程序。

选中文件后，使用 **First subtitle**（首句）、
**Render at time**（按时间渲染）、**Previous**／**Next**（前后字幕）。
时间单位为整数毫秒。预览按目标画布尺寸、使用与导出相同的 libass
和 SRT 预处理渲染，再缩小显示。
它只是 **SDR 样式预览**，不是 SUP 量化／调色板预览，
不模拟 HDR 实际亮度，也不认证 HDR 播放效果。
ASS／SSA 保留原文件样式；预览与转换使用独立渲染实例。

转换开始时固定参数。取消在帧之间检查，可能需要等待一次原生渲染调用；
转换期间关闭窗口会先等待临时输出清理。
首版不含暂停续转、视频播放、单文件独立参数或任务队列持久化。
日志保留最近 500 条，总进度按任务等权计算，不是剩余时间预测。

GUI 同样静态链接第三方原生库，并拒绝第三方 DLL／dylib 导入；
仍依赖系统图形库和驱动。Fyne 内嵌界面字体，它们与字幕字体无关，
构建会从 Go 依赖图收集相应许可证。
CI 已加入四个目标的 GUI 构建；图形、拖放、中文输入和高 DPI，
尤其 Windows ARM64，仍需在对应真机上验收。

## 构建

### 推荐：一条命令编译并打包

在项目目录中执行以下命令即可。**无需再填写 `Binary`、`Prefix`、
`Destination`**：脚本会识别本机架构、查找依赖、运行测试和检查、
静态链接第三方库、收集许可证，并测试可独立运行的程序。
**Windows 和 macOS 现在都只提供静态构建。**

**Windows：在 PowerShell 或命令提示符中运行**

```powershell
.\scripts\build-windows.cmd
```

默认只检查依赖，缺少依赖时会给出提示，**不会自动安装软件**。
如果希望脚本帮助安装，可以显式允许：

```powershell
.\scripts\build-windows.cmd -InstallDependencies
```

此选项允许通过 winget 安装缺少的 Go/MSYS2，并通过 MSYS2 的 pacman
安装对应的编译器、pkgconf 和 libass。自动安装 Go/MSYS2 时，
系统需要已有微软的 **App Installer（应用安装程序）**，即能使用 `winget`。
安装器可能请求管理员授权。安装完成或 MSYS2 核心更新后，
如提示重新打开终端或重试，按提示操作后再次运行命令即可。

如果 MSYS2 已安装在自定义位置，可以指定其根目录：

```powershell
.\scripts\build-windows.cmd -Msys2Root D:\tools\msys64
```

这里填写 MSYS2 根目录，而不是里面的 `ucrt64` 或 `clangarm64` 子目录。
启动器仅对子 PowerShell 进程临时使用执行策略绕过，
不会永久更改系统的执行策略。
启动器使用系统自带的 Windows PowerShell 5.1，无需额外安装 PowerShell 7。
如果存在多个 Go 安装，使用 `PATH` 顺序中的第一个，并检查其版本和本机架构。

**macOS：在终端中运行**

```sh
bash scripts/build-macos.sh
```

允许安装缺少的依赖时使用：

```sh
bash scripts/build-macos.sh --install-dependencies
```

需要事先安装 [Homebrew](https://brew.sh)。显式安装选项允许安装或升级 Go，
以及安装 pkgconf/libass。如果缺少 Apple 命令行工具，脚本会打开系统安装器；
完成安装后重新运行即可。
如果 Homebrew 没有 Graphite2 静态库，显式安装选项还允许在需要时安装 CMake，
并从固定版本、经过 SHA-256 校验的源码构建 Graphite2 1.3.15，
仅安装到项目的 `build/native/`，后续构建会复用。
其他静态库缺失时明确报错，不会退回 dylib，也不会替换或修改 Homebrew 的库。

两个入口都只构建**当前本机架构**，不通过修改 `GOARCH` 交叉编译；
Go、C 工具链及原生库的架构必须匹配。
FFmpeg 不是必需依赖：相应工具可用时会执行独立解码测试及打包输出探测，
不可用时会明确报告跳过。
即使没有开启依赖安装，构建也可能下载 Go 模块，打包还需要下载许可证文本；
默认模式不等于离线模式。

中间编译文件放在 `build/`，可运行的完整程序包放在 `dist/`。
每次运行都会生成唯一命名的包目录、Windows 的 `.zip` 或 macOS 的 `.tar.gz`
压缩包，以及对应的 `.sha256` 校验文件，不会删除之前成功生成的程序包。
运行时只需包内的可执行文件；再分发时应保留许可证和说明。
操作系统自带的库和 Framework 仍然需要。
查看脚本帮助可运行 `.\scripts\build-windows.cmd -?`
或 `bash scripts/build-macos.sh --help`。

### 构建脚本目录

[`scripts/`](./scripts/) 仅保留 `build-macos.sh`、`build-windows.cmd`
和 `build-windows.ps1` 三个入口文件。
打包和原生依赖审计已合并到各平台主脚本，CMD 文件负责启动 PowerShell 脚本。
[`cmd/macos-static/`](./cmd/macos-static/) 是构建时使用的 Go 辅助工具，
负责解析静态库及生成 pkg-config 元数据，不是运行时依赖。
构建脚本测试及 PowerShell 测试数据放在
[`internal/buildscripts/`](./internal/buildscripts/)。

### 仅静态链接及验证

无需指定构建模式。Windows 仍接受旧的 `-Static` 参数以兼容已有命令，
但不再区分两种模式。
这是实际静态链接，不是启动后解压 DLL 的自解压程序。
字幕字体仍使用系统已安装字体，也保留 `--font-dir`，不捆绑字幕字体文件；
可选 GUI 内嵌自身的界面字体。
程序仍依赖 Windows 系统自带的 DLL（包括 Windows 10/11 的系统 UCRT），
但不允许导入第三方渲染库或编译器运行库 DLL。

两个平台均通过 `pkg-config --static` 展开私有依赖，
Windows 强制外部静态链接。
C 代码仍由 GCC/Clang 编译，最终链接则使用同一工具链的
`g++`（UCRT64）或 `clang++`（CLANGARM64），
确保 Graphite2 等 C++ 静态依赖之后正确加入对应的 C++ 运行库。
C++ 驱动会与 C 编译器一起检查，由同一个 MSYS2 编译器软件包提供；
静态版的 DLL 导入审计仍然保留。
整条依赖链都必须有对应架构的静态 `.a` 库；
以 `.dll.a` 结尾的 DLL 导入库不能代替静态库。
缺少库或出现未解析符号时会明确失败，不会自动退回 DLL 版。
原来的动态库打包流程已移除。

静态构建文件位于 `build/windows-<架构>-static/` 或 `build/macos-<架构>-static/`，
完整包位于唯一命名的 `dist/pgs-converter-<系统>-<架构>-static-.../`。
运行时只需其中的 `pgs-converter.exe`（Windows）或 `pgs-converter`（macOS）；
再分发时应保留附带的许可证和说明。
脚本在报告成功前会按 Windows 系统 DLL 白名单审计 PE 导入表，
然后仅复制 EXE 到临时目录，移除 PATH 中的 MSYS2 路径，
实际转换 SRT 和动画 ASS。审计结果保存在 `PE-IMPORTS.txt`，
已安装的软件包版本记录在 `MSYS2-PACKAGES.txt`。
即使某个未知 DLL 恰好位于 System32，也会明确失败，不会默认为系统依赖。

macOS 会生成独立的 `libass.pc`，将第三方 `-l...` 参数替换为明确的静态 `.a`
路径，仅保留 SDK 中的系统库和 Framework 动态链接。
最终使用 Apple C++ 链接驱动；macOS 不支持照搬 Windows 的全局 `-static`。
包内 `MACHO-IMPORTS.txt` 只能包含 `/usr/lib/` 和 `/System/Library/` 的导入，
不附带 dylib，也不再重写动态库加载路径。
`static-archives.txt` 记录实际链接的原生静态库，并为可执行文件应用 ad-hoc 签名，
但不等于 Apple 公证。脚本将可执行文件单独复制到临时目录，
清除 Homebrew 路径及 DYLD 环境变量后，
实际执行 3840×2160、24000/1001 的 SRT 和动画 ASS 转换。

**再分发注意事项：**目前生成的仍是开发包。
静态链接可能包含 FriBidi、GLib 等 LGPL 组件。
仅附许可证文本不足以完成相关义务；公开再分发前，需要审核所有链接组件的许可证，
提供适用的对应源码、目标文件或其他重新链接材料，以及允许用户替换 LGPL 库的重链接说明。
脚本不会自动准备完整的合规材料，详见
[THIRD_PARTY_NOTICES](./THIRD_PARTY_NOTICES) 和包内的 `STATIC-LINKING.txt`。

### 构建前提与平台验证状态

需要 Go 1.24 或更高版本、支持 cgo 的 C 编译器、pkg-config 和 libass 开发文件及静态库。
macOS 私有构建 Graphite2 时还需要 CMake。
macOS ARM64 已使用 libass 0.17.5 完成静态构建、测试、导入表审计、
独立 4K 转换和打包验证。
转换程序运行时不依赖 FFmpeg；开发测试使用 FFmpeg 进行独立解码验证。

Go 和 Homebrew 依赖需要与目标架构一致。
仅设置 `GOARCH` 并不能完成原生 C 依赖的交叉编译。

x64 使用 Windows 原生 Go 和 MSYS2 的 **UCRT64** 工具链；
ARM64 使用 Windows 原生 Go 和 **CLANGARM64** 工具链。
构建入口会配置本机的 C 编译器、C++ 链接驱动、pkg-config 路径和静态链接，
然后审计产物。请使用这些入口，不要用裸 `go build` 绕过静态构建配置。

GitHub Actions 已配置使用上述入口执行 macOS ARM64/x64 和 Windows ARM64/x64
四个目标的构建、测试及静态程序打包流程。**目前只有 macOS ARM64 完成本地运行验证；
其他目标及其打包流程需要通过实际 CI 和干净环境测试后才能确认。**

CI 使用软件包管理器提供的原生依赖，并记录已安装版本；
目前尚未实现所有原生依赖的锁定源码可重现构建，私有 Graphite2 源码已锁定版本和校验值。

## 单文件转换

必须显式指定输出分辨率和帧率。
ASS 的 `PlayRes` 是脚本坐标系统，不能作为可靠的视频分辨率声明。

```sh
pgs-converter convert movie.ass \
  --size 1920x1080 --fps 24000/1001 -o movie.sup

pgs-converter convert movie.srt \
  --size 1920x1080 --fps 24 \
  --font-dir ./fonts --font "Noto Sans CJK SC" \
  --font-size 45 --margin 45 -o movie.sup

pgs-converter convert legacy.ssa \
  --encoding gb18030 --size 1920x1080 --fps 25 -o legacy.sup
```

支持的帧率为：`24000/1001`、`24`、`25`、`30000/1001`、`30`、`50`、
`60000/1001`、`60`。不接受 `23.976` 等近似小数表示。

画布宽高必须能存入 PGS 的 16 位字段，总像素数不得超过 8,294,400，
即 3840 × 2160 的像素数量。工具接受某个尺寸，不代表硬件播放器支持该尺寸。

SRT 默认使用系统 `sans-serif` 字体族，字号和边距默认为画布高度除以 24，
最小为 1 像素。`--font`、`--font-size` 和 `--margin` 仅影响 SRT；
ASS/SSA 保留原脚本样式。

SRT 支持多行文本、重叠事件、HTML 实体、嵌套的 `b`/`i`/`u`、
`font color="#RRGGBB"` 和 `br` 标记。
未知、不配对或不支持的标记会明确报错，不会被静默移除。

转换为 libass 内存中的 ASS 脚本时，会保护原文本中的花括号和反斜杠转义序列，
避免被当作 ASS 指令执行。原始 SRT 毫秒时间会恢复到解析后的字幕事件上，
不会直接截断到 ASS 的百分之一秒精度。

## 批量转换

转换开始时会输出 `START`，之后在标准错误流中显示每个文件的编码进度，
约每 500 毫秒刷新一次（在帧处理之间），并输出初始和结束进度。
百分比按合并后的有效字幕区间内已采样的帧数计算，不重复计算重叠事件，
也不包含空白间隔；它不是视频时间或输出文件大小的百分比。
`100%` 表示编码结束，只有 `OK` 才表示输出已刷新并提交成功。
加载字体或处理单个高开销帧时，进度更新可能延迟。
单文件和批量命令均可添加 `--no-progress` 关闭实时进度，
仍保留警告、结果及汇总。进度采用逐行输出，重定向到日志时也适用。

```sh
pgs-converter batch ./subtitles \
  --recursive --size 1920x1080 --fps 24000/1001 \
  --output-dir ./output --jobs 2

pgs-converter batch one.srt two.ass \
  --size 1920x1080 --fps 24 --output-dir ./output
```

- 默认不递归遍历目录；添加 `--recursive` 后才处理子目录。
- 保留相对目录结构。多个输入根目录分别使用相对于各自根目录的路径。
  多个输入映射到同一输出时，所有冲突项都会在转换前被拒绝，包括仅大小写不同的路径。
- 单个文件失败不会中断其他文件。进度、警告、输入输出映射和最终汇总均写入标准错误流。
- `--jobs` 默认为 1，支持 1 到 32。每个任务拥有独立的 libass 渲染器。
  提高并发数会增加原生字体缓存和图像内存的占用。
  指定 `--jobs 2` 才会同时转换两个文件；不指定时按顺序处理。
  4K 建议先从两个并发任务开始，并留意内存占用。
  并发进度包含输入文件路径，日志统一串行输出，不会交叉写入同一行。
- 默认保护已有文件，只有指定 `--overwrite` 才允许替换。
  转换先写入目标目录中的临时文件，成功后再提交为最终文件。
  禁止覆盖时使用硬链接提交：文件系统不支持硬链接会明确失败，而不会冒险覆盖。
  允许覆盖时使用操作系统的重命名操作；并非所有 Windows 文件系统都保证原子替换。
- Ctrl+C 会停止调度，在渲染或编码操作之间取消活动任务，并清理临时文件。
  不会强制打断正在执行的单次高开销原生操作。

退出码：

| 退出码 | 含义 |
| --- | --- |
| `0` | 成功、显示帮助或显示版本 |
| `1` | 一个或多个文件转换失败 |
| `2` | 命令参数或全局配置错误 |
| `130` | 任务被取消 |

## 字体与文本编码

默认启用系统字体。可以重复指定 `--font-dir`，从多个目录加载额外的 TTF、
OTF 或 TTC 字体文件，不递归扫描子目录。
工具不捆绑字幕字体；若需要不同系统输出一致，请提供相同且具有适当授权的字体文件。

工具会报告 libass 警告、不可用字形诊断以及能够检测到的字体回退失败。
`--strict` 会将这些诊断以及采样后完全不可见的短事件视为文件转换失败。
正常的系统字体选择可能在不发出警告的情况下替换字体族，
因此严格模式**不保证字体完全一致，也不等于完整的字形覆盖预检**。

`--encoding auto` 支持 UTF-8（可带或不带 BOM）以及带 BOM 的 UTF-16。
显式编码选项包括：`utf-8`、`utf-16le`、`utf-16be`、`gb18030` 和 `big5`。

格式错误的输入会被拒绝。旧编码解码路径还会拒绝包含替换字符的解码结果，
避免静默转换已损坏的字节。不进行基于统计的编码猜测。

## 实验性 HDR10/PQ 调色板

默认输出 SDR。若要使用 BT.2020 原色和 ST 2084 PQ 编码调色板颜色：

```sh
pgs-converter convert movie.ass \
  --size 3840x2160 --fps 24000/1001 \
  --color-profile hdr10 --subtitle-white-nits 203 \
  -o movie.hdr.sup
```

HDR 模式下，`--subtitle-white-nits` 默认为 **203 nits**，
接受大于 0 且不超过 10000 的有限数值。SDR 模式不允许显式指定该参数。
高于 300 nits 时会提示观看舒适性风险。
参考白设置表达的是**编码意图**，不保证屏幕实测亮度。HDR 与画布分辨率无关。

HDR 管线将源字幕 RGB 解释为 SDR sRGB/BT.709 图形，先线性化，
再将原色转换为 BT.2020，按参考白亮度缩放，应用 PQ，
最终写入有限范围的 8 位 YCbCr 调色板条目。
它不是简单切换 YCbCr 矩阵，也不会通过缩放透明度模拟亮度。

调色板选择使用确定性的线性光、预乘透明度 RGBA 特征；
PQ 变换以浮点计算完成，之后才进行最终调色板编码。
源渲染器仍使用 libass 的 8 位覆盖率和合成机制。

重要限制：

- 独立 SUP 没有可通用依赖的原色、传递函数或参考白亮度信令。
  播放器可能假设 BT.709、从视频猜测颜色属性，或无视调色板意图而按 SDR 合成字幕。
- **HDR 选项是实验性的。**目前尚未选定并验证目标 HDR 播放器及输出链路。
  解码器能够读取文件，不代表 HDR 颜色正确。
  播放器和显示设备设置还可能重新映射亮度。
- 不生成或修改 HDR10 视频元数据、MaxCLL/MaxFALL，不提供 HLG、
  Dolby Vision 专用处理、视频色调映射或自动视频参数探测。
- 同时需要 SDR 和 HDR 交付时，应分别生成两份 SUP。
  4K 分辨率和 `.hdr.sup` 文件名都不能替代 HDR 信令。

## 渲染与格式限制

字幕按指定帧率的全局帧网格采样，使用整数和有理数计时；
字幕边界取整误差最多为一帧。
完全落在采样帧之间的短事件会被报告，严格模式下会被拒绝。
像素与位置均未变化的画面会被去重，空白区间会被跳过，
并通过显式空组合在字幕间隔和结尾清除画面。

PGS 最多支持 256 个调色板条目。编码器保留透明条目；
颜色数量足够少时，中间 RGB 调色板精确保留源颜色；
超出时使用确定性的加权中位切分量化。
即使不缩减调色板颜色数量，最终 YCbCr 编码仍可能有损。

动画或大面积字幕可能产生较大的文件。
每个变化画面都是完整、自包含的显示组合，尚未使用高级调色板或对象缓存复用。
帧按流式处理，不会将整部影片的所有字幕帧保存在内存中。

SDR 输出使用 BT.709 有限范围调色板转换。
部分解码器对高度不超过 576 行的画布假设使用 BT.601，工具会对此给出警告。
可选 HDR 转换之前，ASS 的 `YCbCr Matrix` 兼容处理以 BT.709 SDR 为渲染目标。
`None` 表示禁用该兼容处理；缺少此头部时遵循传统的 TV.601 解释。
这不会推断视频颜色属性，也不保证与未知视频精确匹配颜色。

不接受负时间、非正持续时间和超出 PGS 字段范围的数值。
不支持 32 位、90 kHz 时间戳回绕，即时间轴范围约为 13.25 小时。
动画保真度受帧率、调色板量化、libass 兼容性和播放器行为限制。
严格蓝光缓冲区及带宽合规、实体播放器认证不在当前范围内。

## 开发与验证

构建入口会使用正确的静态配置运行测试和检查。
完成一次 macOS 构建后，额外测试可执行以下命令（Intel 将 `arm64` 改为 `amd64`）：

```sh
export PKG_CONFIG_PATH="$PWD/build/native/macos-arm64/pkgconfig"
export PKG_CONFIG_LIBDIR="$PKG_CONFIG_PATH"
go test -ldflags "-linkmode=external -extld=/usr/bin/clang++" ./...
go vet ./...
go test -race -ldflags "-linkmode=external -extld=/usr/bin/clang++" ./...
go test ./internal/pgs -run '^$' -fuzz FuzzRLE -fuzztime 5s
go test ./internal/subtitle -run '^$' -fuzz FuzzDecode -fuzztime 5s
```

安装 FFmpeg 后会启用独立 PGS 解码器集成测试，否则该测试会报告跳过。
测试通过 `-copyts` 保留原始时间戳，将解码后的 HD 帧与黑色背景上的
libass 源帧比较，并检查空白帧是否完全没有字幕残留。
活动像素平均 RGB 分量误差上限为 2，峰值分量误差上限为 16。
字体是否可用可能影响渲染结果。
解码精度测试使用 ASS 动画矢量图形，并检查每个采样帧的非透明源颜色不超过 255 种，
将解码误差与系统字体差异、有损调色板量化隔离。
文字移动、淡入淡出、卡拉 OK 及清屏由单独的文字动画流测试覆盖；
有损量化质量使用下述独立数值回归阈值。

其他测试覆盖毫秒时间、SSA 输入、字面文本转义、事件重叠、RLE 边界、
ODS 分片、确定性量化、输出保护、取消和部分成功的批处理。

HDR 测试验证 ST 2084 参考数值、原色转换、调色板黑白点、
实际编码的 203 nits 白色，以及切换色彩配置时几何与透明度保持不变。
这些测试不认证播放器的 HDR 解释行为。
对于固定渐变样例，量化测试要求线性光预乘分量的平均误差不超过 0.025、
峰值不超过 0.15；这些阈值不适用于任意输入。
